# P2P 同步

默认模式下所有文件内容都经过中心服务器转发。内网多机时打开 `--p2p`，让数据在主机之间直连。

```bash
python selfshare.py watch D:\同步盘 --p2p
```

## 分工

| 职责 | 承担者 |
| --- | --- |
| 令牌签发与校验 | 中心服务器 |
| 节点注册、发现、过期剔除 | 中心服务器 |
| 元数据（manifest / commit / history） | 中心服务器 |
| 文件内容传输 | 节点之间直连 |
| 兜底存储 | 中心服务器 |

元数据始终走中心，保证全局顺序一致；只有体积大的 blob 走 P2P。

## 认证模型

token 不在网络上传输。每次拉取：

```text
MAC = HMAC-SHA256(token, "vault:peer_id" + ":" + digest + ":" + nonce)
```

- 请求方把 `MAC` 放在 `X-P2P-MAC` 头
- 提供方用同一 vault 的 token 重算并做常量时间比较
- `nonce` 每次随机，防止重放
- 校验失败返回 401，不泄露任何内容

Python 与 Rust 的 HMAC 实现逐字节一致，两种节点可互为 peer：

```text
python: e98155de7a470a2bdb2d6d577d9142b0b090651c9006fafbea51b2b1300776fe
rust:   e98155de7a470a2bdb2d6d577d9142b0b090651c9006fafbea51b2b1300776fe
```

## 生命周期

1. 节点启动时监听 `0.0.0.0:0`（系统分配端口）
2. 向中心注册 `{peer_id, listen, blobs, host_id}`
3. 每 30 秒心跳
4. 其他节点通过 `GET /api/v/<vault>/peers` 发现
5. 中心按 TTL 300 秒剔除离线节点
6. 正常退出时主动注销

## 回退策略

客户端逐个尝试在线 peer，任一失败立即试下一个；全部失败后回退中心服务器。

输出会标明实际来源：

```text
↓ p2p.txt
  p2p.txt <- peer:127.0.0.1:49376    # 直连成功
  p2p.txt <- server                   # 回退
```

## 注意事项

- 节点按内容哈希在本地目录查找文件；状态库丢失也不影响提供服务
- 同一台机器上的多个节点用 `host + 时间 + 序号` 生成唯一 `peer_id`，避免互相排斥
- 当前仅支持局域网直连。跨 NAT 需要打洞或中继，尚未实现
- P2P 不降低服务端存储需求：提交后的 blob 仍会进入服务端作为兜底
